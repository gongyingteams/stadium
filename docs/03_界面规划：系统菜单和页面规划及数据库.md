## 一、 页面全景规划与命名规范 (共 25 个核心页面)

系统严格按照三大核心支柱与13类基线子系统需求，全量规划25个核心功能页面（覆盖PC端运维管理、统一门户、底层存储配置和移动平板触控）。其中登录页为公开路由，平板页为终端专属路由，动态设备菜单为配置扩展项。

### 1.3 模块深度功能与业务设计说明 (各板块原生内化)

* **【板块一：综合态势总览】**：汇聚场馆2D拓扑（3D为可选增强视图）、各弱电子系统实时在线状态、实时能耗走势与通信链路监控，支持全屏大屏模式与日常工作台模式无缝切换。
* **【板块二：应用聚合门户（支柱二落地点）】**：集中导航大厅卡片化陈列售验票、信息发布、计时计分、录像回放等内部软件，提供一键 SSO 免密单点启动；针对无开放 API 的系统，通过内置安全的反向代理 iframe 容器内嵌展示。
* **【板块三：场馆物联网控制总线】**：
  - 覆盖13类基线子系统的页面与能力映射；页面按功能聚合为扩声、照明、大屏、计时计分、自动升旗、标准时钟、视频监看、媒体播控和动态设备等入口，但不得将页面数量误认为基线子系统数量；
  - **标准时钟与子钟网络**：`ClockSyncMonitor.vue` 实时展示母钟北斗/GPS卫星数、本地与母钟时钟漂移曲线，以及全场子钟按类型（单面/双面/数码）与区域（看台/大厅）的在线故障分布清单；
  - **媒体播控与素材库联动机制**：`MediaPlayConsole.vue` (3.8) 播控列表**直接动态拉取 `MediaResourceLibrary.vue` (4.4) 媒体素材库数据库实体**（`biz_audio_library` 与 `biz_video_library`），保证运维上传新素材后现场控制台秒级更新，彻底杜绝数据源脱节；
  - **流媒体健壮性与断线自动重连**：`VideoLiveMatrix.vue` (3.7) 涉及多路 RTSP/WebRTC/HTTP-FLV 流播放，**内置播放器心跳巡检与指数退避重连机制（1s/3s/5s 梯次重试）**，当场馆局域网交换机抖动或码流闪断时，播放器组件自动感知并平滑重拉流，杜绝监控画面卡死或黑屏；
  - **动态菜单动态挂载**：`DynamicDeviceConsole.vue` 不仅为通用动态容器，还支持根据后台创建的“自定义菜单分组”（如跳水池灯控组、热身馆音响组）在前端侧边栏菜单树中**即时动态挂载展开子菜单**，实现彻底的元数据配置驱动。
* **【板块四：低代码配置驱动中心（支柱三落地点）】**：
  - **全协议配置**：可视化配置串口（COM口/波特率/校验位/停止位/HEX/ASCII）、TCP/UDP长连接与心跳、Modbus寄存器、HTTP接口；
  - **控制按钮绑定**：配置按钮样式、指令模板、执行延时、回传正则解析；
  - **外置硬件适配登记台账 (4.3)**：台账化登记 USB转485、网络串口服务器等外置硬件型号、接线引脚定义与网络拓扑说明，菜单树显式挂载；
  - **媒体素材库**：国歌、颁奖曲、宣传片素材上传，毫秒级读取有效音频时长；
  - **配置模板导入导出**：整套系统配置支持一键导出为标准 JSON 模板，新场馆一键导入秒级克隆；
  - **通信沙箱与模拟调试**：提供脱机模拟沙箱，虚拟下发与接收设备报文，未接硬件前完成全部指令逻辑验证。
* **【板块五：运维监控与安全审计】**：
  - **全链路心跳保活**：实时探针巡检串口与网络连接；
  - **三级告警通知渠道**：统一配置平台界面强弹窗、SMTP 邮件服务器参数、企业微信 Webhook 及微信公众号/小程序模板消息推送策略；
  - **操作审计多维检索与导出**：记录指令报文下发与会话痕迹，支持按时间、操作人、设备类型检索并一键导出 Excel/CSV 留存。
* **【板块六：移动平板现场工作台】**：
  - 针对现场平板横屏触控交互深度定制，大尺寸触控卡片（48px+）；
  - **物理隔离底层配置**：彻底剔除通信协议配置、波特率修改与指令模板编辑菜单，防呆防误触。

## 二、 全局顶部导航栏 (Header Bar) 三段式平衡布局与交互规范

为解决传统界面“中间过空、右侧过挤、左侧文字过长”的失衡痛点，顶部 Header 统一采用**高规格三段式黄金平衡流线（Left Brand/Env · Center Pulse · Right Actions）**：

```
[左侧：系统Logo + 品牌标牌 ── 细分割线 ── 运行环境胶囊(正式环境/测试环境)]
                                      │
[中间：全场综合态势岛 (全链路通信保活 25/1 ── 细分割线 ── 北斗三号高精授时时钟)]
                                      │
[右侧：快捷工具组 (告警铃铛/平板模式/全屏切换/主题调色盘) ── 细分割线 ── 用户角色卡片]
```

### 2.1 顶部 Header 关键交互、美化排列与防呆设计

### 2.3 界面排版与字号层级红线（严禁 11px / 12px 小字准则）

> **【强制设计红线】非必要情况下绝对禁止使用 12px 和 11px 文字（太小看不清）！**

体育场馆弱电集成管控平台面向指挥大屏远距离视认、工控机中控台及多分辨率运维屏幕。11px、12px 的过小文字在高分辨率屏幕或远距离操作下易产生严重边缘发虚、细节辨识不清，极易诱发操作疲劳与工控参数误读。

#### 2.3.1 全站字号阶梯准则 (Typography Scale)

| 字号级别 | 规范像素 (`px`) | 允许适用的界面组件与元素 | 样式设计与对比度约束 |
| :---: | :---: | :--- | :--- |
| **Display 大数** | **`22px ~ 32px`** | 态势总览核心指标数值、大屏比分读数、巨型时钟时分秒 | 等宽字体（`JetBrains Mono` / `Num-Mono`），粗体 700+ |
| **H1 / H2 页面主标题** | **`18px ~ 20px`** | 系统顶栏主标牌、页面主标题、弹窗/抽屉主标题 | 粗体 700，字间距 `+0.3px` |
| **H3 / Card 卡片标题** | **`15px ~ 16px`** | 子系统卡片标题（`.app-name`）、模块子标题、拓扑节点标题 | 粗体 700，在浅色底板上强制使用深邃炭黑蓝（`#0F172A`），绝不允许随深色主题变成发虚浅字 |
| **Body 常规正文/菜单** | **`14px ~ 15px`** | 左侧菜单项（`.item-title`）、操作按钮（`.open-btn`）、表格正文行、表单输入框文本、功能描述段落 | 基础字重 500 ~ 600，行高 `1.45 ~ 1.5`，保证舒适阅读 |
| **Meta 辅助/状态标签** | **`13px ~ 13.5px`** | **【全站文字底线】** 模式状态药丸（`.tag-pill`）、协议参数（`.terminal-mono`）、凭据说明（`.pill-tag`）、次级操作按钮（`.test-connection-btn`）、元数据徽章 | 字重 600，行高 16~18px，配合实色高对比度背景与文字，彻底取代原本发虚的 11px/12px |
| **Small 特殊装饰点** | **`< 13px`** | **【极其受限的豁免范围】仅允许用于纯图形化非文字装饰点**（如微缩模型内部的极小几何点标、无文字的呼吸灯指示圆点），**承载任何业务含义的汉字/英文/数字一律严禁低于 13px**！ |

#### 2.3.2 浅底卡片内文字与组件的“防发虚发暗”对比度规范
1. **卡片标题 (`.app-name`)**：浅色背景卡片内，标题强制绑定深邃高对比颜色（`#0F172A`），杜绝深色模式下变量被误用为白字而导致“白底白字发虚”；
2. **模式标签 (`.mode-tag-wrap`)**：一律使用浅底实色配深色字（例如 API 直通采用绿底 `#DCFCE7` 搭配深翠绿字 `#15803D`），边框实线清晰，杜绝低对比度透明模糊感；
3. **协议代码槽 (`.app-target-bar`)**：背景色保持轻盈浅淡（`rgba(accent, 0.05)`），代码文字为深沉工控色（`#1E293B`），杜绝死黑背景膏药感；
4. **次级测试按钮 (`.test-connection-btn`)**：采用白底微边框（`#FFFFFF` + `1px solid border`），与主按钮形成明确的 Primary / Secondary 主次交互节律，消除死黑过深遮挡问题。

### 2.4 全局容器层级与卡片边框形态规范（双重设计铁律）

> **【设计铁律一】尽量不要套框层级超过 3 层（消除格子压迫感，推广“降框化”色阶差）！**  
> **【设计铁律二】卡片可以有渐变背景色，但是卡片严禁使用“仅左边框”（消除残缺生硬感，采用四周精细边框）！**

#### 2.4.1 容器层级控制与“降框化”原则（Border Demotion Hierarchy）
传统工控界面容易出现“大容器画框、子级容器画框、孙级容器画框、重孙级徽章再画框……”的糟糕视觉效果，导致界面密布密密麻麻的 1px/虚线细框，严重破坏界面呼吸感与空间通透度。

本系统严格确立**最多不超过 3 层的容器边框层级模型**：

```
[第 1 层：大容器/主视窗] ──── [第 2 层：功能卡片/Panel (保留四周 1px 精细框)]
                                      │
                                      └── [第 3 层：内部子容器 (强制 border: none，采用背景色阶差)]
                                                    │
                                                    └── [第 4 层：孙级胶囊/徽章 (强制 border: none，纯色块)]
```

* **第 1 层（大容器/主区域）**：如主视窗展台、网格大背景，由页面留白与轻背景自然形成，非必要不额外叠加重边框；
* **第 2 层（功能卡片 / Panel）**：如 `.app-card`、`.kpi-card`、`.glass-panel`，作为主视觉承载单元，**拥有完整的 1px 四周精细圆角边框与轻微立体投影**；
* **第 3 层（卡片内部子容器）**：如代码展示栏（`.dark-code-block`）、状态栏（`.app-credential-capsule-bar`）、抽屉展开详情等。**【强制红线】严禁使用硬边框或虚线边框（`border: none`）**！必须改用**微弱背景色阶差（Surface Tint，例如 `rgba(var(--th-accent-rgb), 0.04 ~ 0.05)`）+ 圆角**组织视觉层次；
* **第 4 层及更深（胶囊/徽章/标签微元素）**：如 `.target-scheme-badge`、`.pill-tag`、`.stat-pill`。**【强制红线】绝对禁止二次画框**！采用实色或微饱和度背景底块（如 `#DCFCE7`、`#F1F5F9`、`rgba(accent, 0.12)`）+ 高对比实色文字，通透轻盈。

#### 2.4.2 卡片边框形态与高品味渐变背景规范
* **【杜绝仅左边框】**：严禁在卡片或容器容器左侧单独设置 3px/4px 粗线竖条（如旧版 `.kpi-card::before` 仅左侧一条竖立蓝色、`.alarm-flow-card` 仅左粗线）。这种单边框具有强烈的半成品和断裂感；
* **【统一四周精细微边框】**：所有卡片一律使用完整的四周均匀 1px 微边框（`border: 1px solid rgba(var(--th-accent-rgb), 0.22)`），配合 `border-radius: 8px` 精致圆角；
* **【高级微渐变背景底色】**：卡片支持且推荐温润平滑的微渐变背景色（例如 `linear-gradient(145deg, var(--do-bg-card) 0%, rgba(var(--th-accent-rgb), 0.04) 100%)`），增强空间进深感；
* **【状态自适应一体化】**：当卡片表示成功、告警、故障等不同状态时，由**四周完整边框色 + 对应状态色温和微渐变底板**一体化表达（例如危险状态为 `border-color: rgba(danger, 0.35); background: linear-gradient(135deg, var(--do-bg-card) 0%, rgba(danger, 0.05) 100%)`），浑然天成，绝不破坏卡片完整几何形态。

### 5.1 API与iframe双模式

- `TICKETING`和`INFO_PUBLISH`必须记录当前接入模式：`API`或`IFRAME_FALLBACK`。
- API模式必须提供对应业务操作面板；iframe模式必须显示降级状态、代理会话有效期和第三方页面入口。
- Portal卡片由`portal_app`配置动态生成，不得只写死固定卡片。
- 任何应用入口、模式切换、代理会话创建/刷新/注销/失败均写入审计日志。

### 5.2 页面聚合规则

- `/iot/video`可以聚合现场影像、水下影像和电视转播，但必须使用独立子Tab、子系统编码和权限点。
- `/iot/media`可以聚合音频和视频播放，但媒体资源管理仍由`/config/media`提供完整CRUD。
- 动态设备菜单由配置中心生成，不增加24个核心页面数量；动态菜单必须继承设备、动作和终端权限。

## 六、 统一菜单、路由和权限数据规范

### 6.1 菜单节点字段定义

每个静态或动态菜单节点必须具备以下属性：

- `menu_code`：全局唯一菜单编码；
- `parent_id`：父菜单ID（0为根节点）；
- `menu_name`：显示完整全称（用于页面标题、面包屑、文档及Tooltip）；
- `short_name`：**规范缩写别名（严格统一4个汉字，用于PC侧栏导航、移动抽屉、平板导航）**；
- `route_name`：前端Vue路由名称；
- `route_path`：前端路由地址；
- `component_name`：前端Vue组件路径；
- `icon_code`：纯矢量SVG图标编码；
- `sort_order`：排序权重；
- `terminal_scope`：`PC`、`TABLET`或`ALL`；
- `baseline_flag`：是否属于附件基线（1=基线, 0=扩展项）；
- `dynamic_flag`：是否为配置动态生成（1=动态, 0=静态）；
- `permission_code`：所需访问权限编码；
- `status`：启用/停用状态（1=启用, 0=禁用）。

> 登录页为公开路由，不进入登录后PC侧边栏；平板页为`TABLET`专属入口；动态菜单不得覆盖静态路由或绕过权限校验。

### 6.2 权限模型

权限按以下层级组织：

> 系统 → 子系统 → 设备实例 → 页面 → 控件 → 动作 → 数据操作 → 终端类型

必须为以下高风险动作设置独立权限：

- 真实硬件指令下发；
- 升旗急停；
- 照明全灭；
- 大屏切源；
- 媒体上传、编辑、删除；
- 配置导入、导出和回滚；
- Mock切换；
- 告警确认、静音和关闭；
- 审计导出；
- iframe应用访问和API操作。

前端隐藏菜单不是安全边界，所有后端接口必须重新校验用户、角色、资源、动作和终端类型。

## 八、 数据库公共规范与验收约束

1. 所有业务表必须具备主键、创建时间、更新时间、状态字段；重要操作增加创建人、更新人和版本号。
2. 所有跨域关系必须使用外键或明确的逻辑外键，并建立常用检索索引：用户、设备、子系统、事件类型、状态、时间、Trace ID。
3. 配置、凭证和Ticket不得明文存储；导出JSON默认脱敏Token、密码、密钥和第三方凭证。
4. 媒体、设备、菜单、模板删除默认采用软删除；存在业务引用时禁止直接删除，或必须先解除引用并记录审计。
5. 告警原始事件、审计日志、SLO结果、Mock日志和配置版本不得因页面关闭、告警关闭或菜单删除而丢失。
6. 13类基线子系统必须能从数据库追溯到菜单入口、页面/子Tab、权限、设备、协议、轮询、告警和审计对象。
7. 数据库模型应与01文档和最终`install.sql`保持同一版本；表结构变更必须提供迁移脚本和回滚方案。
8. 3D、AI、PIP、多路投屏、BAS、智慧安防、有线电视等扩展能力必须通过`baseline_flag`或独立扩展编码与附件基线隔离。

## 九、 与02原型的统一约束

- 统一采用25个核心页面和25条核心路由；PC端静态菜单为23个节点，登录和平板为专属入口，动态设备菜单为配置扩展项。
- 菜单显示严格执行**全称（用于标题/面包屑）与统一4字别名（用于左侧导航栏/快速筛选）双向绑定**。
- **主题色彩约束**：全站原生内置4款精校蓝色主题（经典商务蓝/科技深蓝/现代亮蓝/远山青蓝），配备2×2真实微缩界面模型调色盘，严禁任何蓝紫渐变。
- **字号排版红线**：全站非必要情况下绝对禁止使用 12px 和 11px 文字；正文一律 ≥ 14px，标签及辅助参数一律 ≥ 13px，保证大屏和工控视窗下的极致可读性。
- SLO必须支持“退出全部系统”、逐应用结果、失败重试和代理会话销毁。
- iframe必须使用域名/路径白名单、Cookie隔离、CSP、sandbox、短时效一次性Ticket和跨域消息校验。
- 升旗急停必须最高优先级立即执行，不得被普通确认弹窗阻塞；普通高危动作才使用二次确认。
- 媒体资源必须支持音频和视频新增、编辑、删除、分类、检索、播放/试听及引用检查。
- 平板端隐藏配置菜单不能替代后端权限校验。
- 所有3D、AI、PIP和多路投屏功能均为可选扩展，必须提供2D、普通布局和无AI数据的降级路径。
- 效果图文件必须与`design_mockups`实际文件保持一致；不存在的文件不得作为已交付物标注。
